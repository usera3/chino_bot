# zhinai-bot-v3 项目规划总结（管家模式）

## 🎯 核心思想

**v3 = 智能管家中枢 + 插件生态**

管家只负责"调度"，具体功能全部由"插件"实现。

---

## 💡 关键设计决策

### 1. 管家 vs 传统 Agent

| 对比项 | 传统 Agent | 管家模式 |
|--------|-----------|---------|
| 职责 | 功能实现 + 调度 | 只负责调度 |
| 代码量 | ~5000 行 | ~500 行 |
| 扩展性 | 需改代码 | 添加插件 |
| 维护性 | 耦合严重 | 高度解耦 |

### 2. 插件化策略

```
核心功能（情感、角色、记忆）→ 插件（优先伪代码）
具体功能（邮件、天气、搜索）→ NoneBot 插件商店
```

### 3. 实现优先级

1. **P0**: 管家框架（Butler + PluginManager）
2. **P1**: 核心插件接口（伪代码）
3. **P1**: NoneBot 插件适配器
4. **P2**: 真实插件实现（逐步替换伪代码）

## 📦 核心组件

### 1. Butler（管家中枢）
**文件**: `core/butler.py`  
**代码量**: ~200 行  
**职责**:
- 理解用户意图
- 规划任务步骤
- 调度插件执行
- 整合执行结果

**不负责**:
- ❌ 具体功能实现
- ❌ 数据存储
- ❌ 业务逻辑

### 2. PluginManager（插件管理器）
**文件**: `core/plugin_manager.py`  
**代码量**: ~150 行  
**职责**:
- 插件注册与发现
- 插件生命周期管理
- 工具调用路由

### 3. Plugin（插件基类）
**文件**: `plugins/base_plugin.py`  
**代码量**: ~50 行  
**接口**:
```python
class Plugin(ABC):
    @property
    def name(self) -> str: pass
    
    def get_tools(self) -> list[BaseTool]: pass
    
    async def on_load(self): pass
    async def on_unload(self): pass
```

### 4. NoneBotPluginAdapter（插件适配器）
**文件**: `adapters/nonebot_adapter.py`  
**代码量**: ~300 行  
**职责**:
- 扫描 NoneBot 插件
- 转换为 v3 Plugin
- 参数映射

## 💬 常见问题

### Q1: 为什么核心插件用伪代码？
**A**: 
- 先定义接口，保证架构清晰
- 后续可以用 NoneBot 插件或自己实现替换
- 保持接口不变，不影响管家

### Q2: 如何集成 NoneBot 插件？
**A**:
```bash
# 1. 安装插件
poetry add nonebot-plugin-weather

# 2. 自动适配（无需手动配置）
# NoneBotPluginAdapter 会自动发现并转换
```

### Q3: 插件故障怎么办？
**A**:
- 插件故障不影响管家
- 管家会捕获异常并优雅降级
- 提示用户该功能暂时不可用

### Q4: 如何开发新插件？
**A**:
```python
# 1. 继承 Plugin 基类
class MyPlugin(Plugin):
    name = "my_plugin"
    
    def get_tools(self):
        return [MyTool()]

# 2. 放到 plugins/ 目录
# 3. 自动被发现和注册
```

## 🎉 总结

### 核心亮点
1. **管家模式**: 调度中枢 + 插件生态
2. **高度解耦**: 核心代码 < 500 行
3. **易于扩展**: 新插件 < 5 分钟
4. **插件化**: 优先使用 NoneBot 插件商店

### 开发策略
1. **先框架**: 管家 + 插件管理器
2. **后插件**: 伪代码 → 真实实现
3. **重适配**: NoneBot 插件自动转换
4. **持续优化**: 逐步替换伪代码

### 预期成果
- ✅ 架构清晰、易维护
- ✅ 功能丰富、易扩展
- ✅ 开发高效、易集成
- ✅ 全面超越 new-bot
